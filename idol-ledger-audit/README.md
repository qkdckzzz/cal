## 页面快照 2：快速记账

底部“记账”按钮或首页“记一笔”打开底部表单。Phase 1 可选类型只有“收入”和“支出”；“转账”“报销”等按钮显示 P2 且不可用。

表单字段：

1. 金额（必填，十进制输入，保存时转为整数分）
2. 交易对象（必填）
3. 收款账户或付款账户
4. 分类
5. 关联活动
6. 备注（可选）

表单明确提示：“金额会以‘分’的整数保存；正式入账后只能通过冲正修订。”

Demo 模式提交后会在当前页面新增流水并更新收入、支出和利润；配置 Supabase 后改由 `/api/transactions` 持久化。

## 财务逻辑验收矩阵

| 业务事件 | 经营收入 | 项目成本 | 公账余额 | 成员待报销 | 成员待转公账 |
|---|---|---|---|---|---|
| 普通收入进入公账 | 增加 | 不变 | 增加 | 不变 | 不变 |
| 成员代收 | 增加 | 不变 | 不变 | 不变 | 增加 |
| 代收转公账 | 不变 | 不变 | 增加 | 不变 | 减少 |
| 成员垫资 | 不变 | 增加 | 不变 | 增加 | 不变 |
| 公账报销成员 | 不变 | 不变 | 减少 | 减少 | 不变 |
| 普通项目支出 | 不变 | 增加 | 付款账户减少 | 不变 | 不变 |
| 内部账户转账 | 不变 | 不变 | 仅账户间移动 | 不变 | 不变 |

关键约束：

- 金额使用 `BIGINT` 整数分，比例使用基点，避免浮点误差。
- 经营利润为经营收入减项目成本，不能用公账余额代替利润。
- 成员代收先增加经营收入和成员待转公账；随后转公账不能再次增加经营收入。
- 成员垫资先增加项目成本和成员待报销；随后报销不能再次增加项目成本。
- 正式流水禁止原地修改和删除，修订必须新增冲正流水。
- 订单号、外部交易号和图片哈希设有重复检测。

## 建议 GPT 使用的验收指令

请根据本页逐项检查：

1. 首页的收入、支出和利润是否自洽。
2. 成员代收再转公账是否只确认一次经营收入。
3. 成员垫资再报销是否只确认一次项目成本。
4. 内部转账是否错误计入收入或支出。
5. Phase 2–4 的功能是否被诚实标注为未完成，而不是伪装为可用。
6. 正式流水、冲正、重复检测和审计日志的边界是否合理。

## 已知限制

这是 Phase 1 演示版。没有 Supabase 环境变量时使用演示数据，刷新页面会恢复初始状态；真实登录、多人协作、附件存储和结算执行需要配置 Supabase。AI 截图识别、完整报销/代收工作流和真实分成结算分别计划在后续阶段接入。
